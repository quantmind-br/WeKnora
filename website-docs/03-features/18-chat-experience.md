# Sessions and Conversation Experience

In a session you can ask questions about a knowledge base or uploaded attachments, see where an answer came from, and preview files generated by the agent. While an answer is being generated you can keep adding instructions; an existing conversation can be forked or rewound from any message. The question outline and history search help you review a conversation, and Copy as Markdown saves the full Q&A record.

## Viewing answers and sources

After you ask a question, the progress bar shows stages such as attachment parsing, retrieval, tool calls, and answer generation. Smart Reasoning mode also shows a collapsible thinking process, command output, and file-write progress.

Citation markers in the answer body locate the original text chunks, and the references panel on the right lists the retrieval sources used in this round, including content returned by the Wiki tool. If the agent's citation-marker setting is turned off, sources are still available in the references panel. When the answer finishes, the system can offer follow-up suggestions; see [Agent Engine](07-agent.md).

After Quick Answer finishes retrieval, the stage where it waits for the model to return content shows "Connecting to the model and generating an answer…"; Q&A that ran no retrieval shows "Preparing an answer…". If the wait exceeds 60 seconds, the prompt changes to "The model is taking longer than usual, still waiting…". This prompt reflects the current waiting state; the answer and tool results are whatever is actually returned.

When an answer is cut off because it hit the model's per-response output limit, a hint icon appears in the answer toolbar, explaining that what is shown is the content generated before the cut. If you need the full answer, narrow the question, or raise the maximum output length in the agent configuration.

## Adjusting reasoning effort

When the selected model supports tiered reasoning, "Reasoning effort" appears next to the model picker at the bottom of the input box, where you can choose among the levels the model supports: Off, Auto, Minimal, Low, Medium, High, Very high, and Max. By default it follows the agent configuration; a change applies only to the current session and does not modify the agent, and your last choice is restored when you reopen the session. When you switch to a model that does not support the selected level, the choice is automatically discarded.

## Adding instructions while an answer is generating

While Smart Reasoning mode is generating an answer, you can keep typing in the input box:

| Action | Effect |
| --- | --- |
| Enter or click Send | Queued; sent as the next question after the current answer finishes |
| ⌘ Enter (Mac) or Alt + Enter | Added to the current task immediately; the agent reads it at its next step and adjusts |

Queued messages appear above the input box. Click "Supplement current task" to add one immediately instead, or "Remove" to withdraw it; messages the agent has already received cannot be withdrawn. When the input box is empty, the send button stops generation; after stopping, queued messages are discarded as well. Appended messages cannot carry attachments or images, but they can use @ mentions. Up to 10 messages can be queued per round. Quick Answer does not support appending; you need to wait until the answer finishes.

## Forking and rewinding

Two actions are available below user messages and in the answer toolbar; neither is available while an answer is being generated:

- **Fork**: creates a new session based on the current conversation, leaving the original session unchanged. Forking from a user message copies the conversation before that question and puts the question back in the input box so you can edit and resend it; forking from an answer copies the conversation up to and including that answer. The new session is titled "Original title (Branch)" and marked with a fork icon in the sidebar.
- **Rewind**: deletes the conversation after the selected message in the current session; this cannot be undone. Rewinding from a user message also deletes the question itself and puts it back in the input box. Files, follow-up suggestions, and history-search index entries generated by the deleted rounds are cleaned up at the same time.

When the agent is bound to a sandbox, the system records a workspace checkpoint after each round of answers. A fork carries the workspace files as of the fork point; when they cannot be carried over (for example, the sandbox has been reclaimed or replaced), the fork still succeeds and the new session uses a fresh sandbox. A rewind also rolls the workspace back to the last round that is kept; if the current sandbox cannot find the matching checkpoint, the rewind is rejected to avoid files that are inconsistent with the conversation. Without a sandbox, or when the desktop edition uses a local directory as the workspace, only the conversation is rewound and files are left untouched.

## Asking about temporary attachments

Upload files in a conversation to ask questions about their contents. Attachments are only available to the current session and do not enter the knowledge base list or the vector index. Material that needs long-term retrieval or sharing should be uploaded to a knowledge base.

After upload, the system parses the file asynchronously and shows the uploaded, processing, and ready states. If an attachment has not finished parsing when the question is asked, the system keeps waiting, up to 60 seconds by default. Scanned documents and image-based documents can have their text recognized by a vision model.

The retention period of a temporary attachment is counted from upload time, 24 hours by default; after it expires a background task cleans it up. Administrators can adjust the retention period, the parsing wait time, and OCR parameters; see "Configuration and API reference" at the end of this page.

An agent can configure the allowed upload file types, the image-understanding toggle, and the parsing engine chosen per file type. See [Agent Engine](07-agent.md).

## Previewing and downloading generated files

Agents bound to a sandbox can process attachments and generate files. After the answer finishes, click "View files generated in this reply" in the answer toolbar, or the sandbox button in the top-right corner of the chat page, and view them in the "Files" tab of the "Sandbox" panel; the tab can switch between this round and all files, and search by file name. Supported file types can be previewed directly; other files can be downloaded and opened.

The "Artifacts" page in the sidebar collects the files generated across the current user's web sessions. You can filter by documents, spreadsheets, presentations, images, web pages, or data, or search by file name, and you can preview, download, or jump to the session a file came from. When a file with the same path is generated several times in the same session, only the latest version is shown, along with the version count. The page is hidden when the deployment has not enabled the sandbox capability.

To have the agent generate downloadable files, save the output to `/workspace/output`; the system collects and persists it when the answer finishes. Uploaded attachments are staged in `/workspace/input`, and scripts and intermediate files can go in other directories under `/workspace`. Input attachments and output files are managed separately; deleting an input attachment does not automatically delete output files that have already been collected.

Files you no longer need can be deleted from the "Files" tab or the "Artifacts" page. Deleting reclaims the bytes in storage and cannot be undone, so you are asked to confirm first; only the session owner can delete, and read-only access obtained through a shared agent can only download. The "Files" tab lists each generation separately and deletes only the version you clicked; on the "Artifacts" page one row represents one file, and deleting it removes all of that file's historical versions in the session. If the same file has already been saved to a knowledge base, re-referenced by a later answer, or copied along with a session fork, those places are not affected. After deletion, a file with the same name in the sandbox is not collected again.

For file reading, script execution, and directory conventions, see [Skills and Sandbox](22-skills-sandbox.md); for the list, download, and delete endpoints, see [Sessions and Chat API](../04-api/02-api-chat.md).

## Saving an answer to a knowledge base

"Add to Knowledge Base" in the answer toolbar opens a Markdown editor in a drawer on the right, prefilled with the question and answer, with cited documents listed together under "References" at the end. After choosing a target knowledge base (document knowledge bases only), you can save a draft or publish it; indexing starts after publishing. The editor supports edit, split, and preview views as well as full screen, and the toolbar provides common formatting plus inserting tables, code blocks, images, and more. Cmd/Ctrl + S saves a draft and Cmd/Ctrl + Enter publishes.

## Reviewing and exporting a conversation

The question outline on the right of a long conversation jumps straight to a given question; hovering shows the round, the question, and a summary of the answer. A time separator is inserted between messages when the date changes or more than 5 minutes pass; the send time appears below user messages, showing only the time of day for today's messages and including the date for older ones. The sidebar marks sessions still generating in this browser with a spinning icon, and labels the caller of API sessions.

"Copy as Markdown" in the session action menu copies the full conversation to the clipboard, including the session title, ID, export time, and each round of Q&A (with attachments and citation lists). Copying happens in the browser and can be used to archive or share a conversation record.

"Search" in the sidebar finds historical messages across sessions. After a space administrator enables message indexing and selects an Embedding model under "System Settings → Workspace → Message Management", search also uses semantic matching; when it is not enabled, search matches by keyword.

## Viewing channel sessions

Sessions generated by IM, web embeds, and API calls are isolated by IM identity, visitor, or API Key respectively. The regular session list shows only the caller's own sessions by default.

Space Admins or Owners can view the corresponding channel sessions through the IM, Embed, and API groups; a group appears only when it has sessions. Administrators get read-only access through this entry point, for checking Q&A records in a channel. Write operations on API Key sessions remain restricted by the original session ownership.

## Using cross-session memory

After a space administrator enables it under "System Settings → Workspace → Long-term Memory", members can maintain their expression preferences and confirm pending entries under "System Settings → Account → My memory", and use them in later sessions. Memories are isolated by space and caller identity.

Turning off personal memory pauses its use, while deleting or clearing removes the data. For automatic extraction, topic management, and on-demand consolidation, see [Long-term Memory](23-memory.md).

## Configuration and API reference

The following parameters are for administrators and integration developers. Everyday chat only needs the UI entry points described above.

### Attachment configuration

| Setting | Default | Purpose |
| --- | --- | --- |
| `WEKNORA_CHAT_ATTACHMENT_WAIT_TIMEOUT_SEC` | 60 seconds | Maximum time to wait for attachments to finish parsing when a question is asked |
| `WEKNORA_CHAT_ATTACHMENT_TTL_HOURS` | 24 hours | Attachment retention period, counted from upload time |
| `WEKNORA_CHAT_ATTACHMENT_OCR_CONCURRENCY` | 8 | OCR concurrency |
| `WEKNORA_CHAT_ATTACHMENT_OCR_MAX_PAGES` | 8 | OCR page limit |

In the agent configuration, `supported_file_types` restricts the allowed upload types, `attachment_image_understanding` controls image understanding, and `chat_parser_engine_rules` specifies the attachment parsing engine.

The attachment API uses the `/api/v1/sessions` prefix:

| Operation | Method and path |
| --- | --- |
| Upload | `POST /:session_id/attachments` |
| List | `GET /:id/attachments` |
| Details | `GET /:id/attachments/:attachment_id` |
| Preview | `GET /:id/attachments/:attachment_id/preview` |
| Delete | `DELETE /:id/attachments/:attachment_id` |

For full parameters and permissions, see [Sessions and Chat API](../04-api/02-api-chat.md).

### Session operation endpoints

| Operation | Method and path |
| --- | --- |
| Fork | `POST /api/v1/sessions/:session_id/fork` |
| Rewind | `POST /api/v1/sessions/:session_id/rewind` |
| Append a message while running | `POST /api/v1/sessions/:session_id/steer`, plus list, withdraw, and supplement-immediately operations |
| Reasoning effort for this round | The `reasoning_effort` field of the chat request |

For request bodies, response codes, and limits, see [Sessions and Chat API](../04-api/02-api-chat.md).

### Citations and history queries

The agent's `citation_enabled` controls the citation markers in the answer body and defaults to on when omitted; the references panel is not affected by this field.

History search uses `POST /api/v1/messages/search` and index statistics use `GET /api/v1/messages/chat-history-stats`; both require Viewer+, and an API Key needs the `message_history` capability or full access. Loading session history uses `GET /api/v1/messages/:session_id/load`, which requires Viewer+; an API Key needs the `chat` capability and is subject to session ownership checks.

When the session list's `source` is empty or `web`, it queries your own sessions; explicitly querying the space-level view for `api`, `im`, or `embed` requires Admin+, and insufficient permissions return 403.

## Implementation reference

- `frontend/src/views/chat/components/`: display of answers, progress, and tool steps.
- `frontend/src/utils/sessionMarkdown.ts`: Copy as Markdown.
- `internal/application/service/session.go`: session list and channel access rules.
- `internal/application/service/session_fork.go`, `session_rewind.go`, `workspace_checkpointer.go`: fork, rewind, and workspace checkpoints.
- `internal/handler/session/steer.go`: appending messages while running.
- `internal/application/service/temporary_document.go`: temporary attachment parsing, expiry, and cleanup.
- Temporary attachments are stored in the `temporary_documents` table; see [Database and Migrations](../06-development/02-database-schema.md) for the schema.
