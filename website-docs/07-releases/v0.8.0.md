# v0.8.0 Release Notes

Release date: 2026-09-03

The theme of v0.8.0 is letting agents actually get work done: skills become a resource managed centrally within the space, running scripts, processing files and producing deliverables in a session-level sandbox; new cross-session long-term memory lets agents remember the preferences and information you have confirmed. In addition, Office documents can be parsed directly in the application, and GitLab and Tencent IMA data sources, LiteLLM model integration and a DeepSeek Harness plugin have been added.

Before upgrading from v0.7.x, please read the [upgrade notes](#upgrade-notes) first. For the full list of changes, see the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

## Skill sandbox {#skill-sandbox}

Agent skills run in a session-level sandbox: each conversation has its own sandbox, and multi-turn tasks share the same workspace. Running commands, reading, writing and editing files, processing uploaded attachments and collecting generated files all happen in this workspace.

<Screenshot
  src="/screenshots/skill-sandbox-chat.png"
  caption="The agent generates a Word document from the knowledge base and previews the generated file next to the conversation" />

- **Three backends**: Docker (single machine or self-hosted), E2B (cloud or a self-hosted E2B-compatible control plane) and CubeSandbox, using the same remote protocol.
- **Per-space configuration**: image, CPU / memory, lifetime, DNS, templates and snapshots can all be configured per space; admins can also set a network policy for each configuration, such as denying egress by default and allow / deny lists.
- **Docker backend disabled by default**: mounting `docker.sock` is equivalent to root on the host, so it must be enabled under "System settings → Network security" or by setting `WEKNORA_SANDBOX_DOCKER_ENABLED=true`.
- **Generated files**: files generated in the sandbox are collected into each message's artifact drawer, where they can be previewed and downloaded, with a notification when new files appear.
- **Long-task compaction**: long-running tasks in the sandbox compact the tool call history rather than truncating or rewriting files; a stable prompt prefix plus cache markers improves the cache hit rate for Anthropic and OpenAI-compatible APIs. Token usage for each conversation turn is also recorded.

See [Skill Catalog & Sandbox](../03-features/22-skills-sandbox.md) and [Sandbox Deployment and Troubleshooting](../06-development/04-sandbox-deployment.md).

## Space skill catalog {#skill-catalog}

Skills become first-class resources within the space instead of files sitting next to the service process.

<Screenshot
  src="/screenshots/skill-catalog.png"
  caption="Space skill catalog: each skill and the sandboxes it is installed in" />

- **Multiple installation sources**: ClawHub, SkillHub / skills.sh, GitHub / GitLab links, or an uploaded ZIP.
- **Per-sandbox installation**: each installation produces a snapshot on the selected sandbox configuration, with live installation progress and installation logs; it can be stopped midway or reinstalled; uninstalling from a sandbox keeps the package in the catalog.
- **Online viewing and editing**: installed skill files can be browsed and edited in settings; agents can also modify skill files through `write_skill_file` and `edit_skill_file`, and `shell_exec` no longer requires a skill to be installed first.
- **Environment variables**: personal and space-level skill environment variables are injected at execution time and are never read back after saving.
- @-mentioning a skill no longer unexpectedly narrows the range of skills available to the agent.

## Cross-session long-term memory {#memory}

A new long-term memory capability, independent of the Neo4j-based conversation memory removed in v0.7.1.

- **Opt-in**: once enabled for the space, each user can still turn it off for themselves.
- **Categorized memories**: memories are divided into five categories (profile, preference, fact, task and interest), and can be written explicitly or extracted automatically in the background.
- **You confirm**: automatically inferred memories stay pending until you confirm them and do not take effect directly.
- **How it is used**: profile and preferences are included in every conversation turn; situational facts are recalled by keyword, and semantic recall can also be enabled; agents can query on demand with `search_memory`. Frequently cited documents get a higher weight during retrieval.
- Settings, items, topics, document associations, confirm / reject, export and forced consolidation are all provided through `/api/v1/memory/*`, restricted to full-access API Keys, and always operate on the caller themselves.

See [Long-term Memory](../03-features/23-memory.md) and the [Long-term Memory API](../04-api/02-api-memory.md).

## Document parsing and data sources {#parsing-and-sources}

- **In-app anydoc parsing**: Office documents that anydoc can convert, such as doc, docx, ppt and pptx, can be parsed directly inside the Go application without going through docreader. The application image links anydoc by default.
- **XMind outline parsing**: `.xmind` files are parsed into outlines and indexed like other documents.
- **Automatic document tagging**: after parsing, the chat model can pick suitable tags from the knowledge base's existing tags and add them incrementally, without creating new tags or overwriting manually added ones.
- **GitLab and Tencent IMA data sources**: GitLab projects can be synced as knowledge sources; Tencent IMA notes are synced through the notes OpenAPI, with automatic retries on transient errors.
- **Parsing quality**: vertically merged DOCX cells and table text are preserved; images embedded in PDFs no longer come out all black; failed web page fetches report an error directly instead of adding the error page to the knowledge base.

See [Document Parsing](../03-features/03-document-parsing.md) and [Data Source Import](../03-features/10-datasource.md).

## Models, search and ecosystem {#ecosystem}

- **LiteLLM**: integrated as a first-class provider for chat, embedding and rerank models; a single gateway address can forward to multiple upstream models.
- **Exa and Metaso search**: two new web search providers.
- **DeepSeek Harness plugin**: the official npm package [`@wxg-prc-cpg/dsh-weknora`](https://www.npmjs.com/package/@wxg-prc-cpg/dsh-weknora) provides four read-only tools, `weknora_search`, `weknora_read_document`, `weknora_ask` and `weknora_list_knowledge_bases`, letting the DeepSeek Harness coding agent retrieve knowledge from WeKnora. See [DeepSeek Harness](../05-clients/08-deepseek-harness.md).

## Chat experience {#chat}

- Longer conversations show a question outline for quick navigation; messages are separated by time.
- `shell_exec` is shown as a "command + output" card; tool cards show the sandbox file list and skill name.
- During streaming output, Mermaid diagrams stay rendered instead of flickering repeatedly.

## Accounts and security {#security}

- **OIDC signature verification**: ID Token signatures are verified via JWKS; the new `/auth/oidc/start` allows jumping directly to login.
- **Optional complex passwords**: when enabled, registration, password changes and admin password resets all require uppercase and lowercase letters, digits and special characters (`WEKNORA_AUTH_COMPLEX_PASSWORD_ENABLED` or system settings).
- **Admin-created users**: platform admins can create users directly in the console without an invitation link.
- **Invitation flow**: invitations to already registered users can be accepted automatically; in invite-only mode, share links first guide visitors to log in before joining the space.
- **Sandbox security**: all execution in the Docker sandbox runs as the sandbox user (uid 1000), symlink operations that could escape the workspace are closed off, and zombie processes left by cancelled executions are reaped.

## Upgrade notes {#upgrade-notes}

| Change | What to do |
| --- | --- |
| The host-process (Local) sandbox backend has been removed | Existing Local sandbox configurations must be recreated using Docker (must be enabled manually), E2B or Cube |
| The Docker sandbox backend is disabled by default | Enable it under "System settings → Network security" or set `WEKNORA_SANDBOX_DOCKER_ENABLED=true` |
| With complex passwords enabled, registration and password change requests that do not meet the rules are rejected | Notify users of the new password requirements before enabling it |

Database migrations: `000080`–`000090` for PostgreSQL and `000003`–`000012` for SQLite. The Docker sandbox backend requires `appuser` in the app container to belong to the user group that owns `docker.sock`.

## Other improvements and fixes {#other-changes}

- **Retrieval**: MMR selection is now computed incrementally; hybrid retrieval honors `resource_urls=public`; `MatchCount=0` no longer truncates all results; deleted images are no longer retrieved.
- **IM**: Feishu long connections support reverse proxies, and streaming cards show progress in full-output mode; several compatibility improvements for WeCom, DingTalk and Yunzhijia; IM Q&A supports file attachments.
- **Spaces and documents**: switching spaces remembers the last used space; passwords can be changed in personal settings; drag-and-drop folder uploads keep the folder structure; document summaries are editable, and chunk lists are paginated.
- **Deployment capabilities**: unregistered modules are hidden in menus and settings (`GET /system/capabilities`), so slimmed-down editions such as Lite no longer show missing features.
- **Bug fixes**: high-risk system settings read the latest saved value; Feishu streaming cards no longer get stuck in progress; deleting a referenced model shows the reference details; shared knowledge bases no longer show 0 documents in the agent context; built-in agent names and descriptions follow the UI language.

For the full list, see the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).
