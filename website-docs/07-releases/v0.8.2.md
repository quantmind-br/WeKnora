# v0.8.2 Release Notes

Release date: 2026-09-24

v0.8.2 takes agents beyond the chat box: they can operate the browser on your computer; knowledge bases can be published as an MCP Server to Claude, Cursor and other AI tools; and conversations are more controllable, letting you add requirements midway, fork or rewind. The sandbox gains an interactive terminal and a graphical desktop, model integration now configures itself from a provider catalog, and there are further updates including Confluence and DingTalk document data sources and a Japanese UI.

Before upgrading from v0.8.0, please read the [upgrade notes](#upgrade-notes) first. For the full list of changes, see the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

## Local browser {#local-browser}

Smart reasoning conversations can directly operate Chrome or Edge on your computer. The browser connects to WeKnora through Tencent's open-source [BrowserSkill](https://github.com/Tencent/BrowserSkill) extension, and the agent opens pages, clicks, fills in forms and reads content in a separate task window, then reports the results back in the conversation.

<Screenshot
  src="/screenshots/local-browser-task.png"
  caption="The agent looks up the latest GitHub Release and then fills in an order form; the task preview is at the bottom right of the conversation" />

- **Controllable from the conversation**: the task preview is shown in the conversation, where you can pause, resume or end it at any time, or jump to the browser to view the corresponding page.
- **Hands over to you when a person is needed**: for logins, CAPTCHAs or steps that need authorization, the agent requests human assistance; once you finish in the browser, it carries on.
- **Pair once, use everywhere**: copy the pairing link from "Toolbox → Browser connection" and paste it into the extension. Multiple conversations in the same space share this browser's authorization, and it is only used after turning on the "Local browser" switch in the input box.

<Screenshot
  src="/screenshots/browser-connection.png"
  caption="Toolbox → Browser connection: extension version, connection status and the web actions the agent can perform" />

The app image for Docker deployments already includes the BrowserSkill service and the matching extension, so usually no extra configuration is needed; multi-replica deployments need to configure node-to-node addresses and a shared secret. See [Local Browser](../05-clients/09-local-browser.md).

## Built-in MCP Server {#mcp-server}

Every space can publish its knowledge bases as an MCP service, letting MCP-capable clients such as Claude Desktop, Cursor, Claude Code and VS Code retrieve and ask questions directly, with no separate MCP process to deploy.

<Screenshot
  src="/screenshots/mcp-server-endpoint.png"
  caption="Settings → Publish & Integrations → MCP Server: endpoint address and client configuration" />

- Create an endpoint under "Settings → Publish & Integrations → MCP Server", choosing the accessible knowledge bases and the tools to expose.
- Tools come in four groups: retrieval and reading, Q&A (runs the agent specified by the endpoint), Wiki, and writing; write tools are off by default.
- Each endpoint has its own token and call rate limit (60 per minute by default), and the token can be rotated at any time.
- The page provides ready-made configuration snippets for Cursor, VS Code and Claude Desktop, and a one-line command for Claude Code.

The Python `mcp-server/` previously in the repository has been marked as deprecated. See [MCP Integration](../03-features/08-mcp.md#serving-external-clients).

## Conversation control {#conversation-control}

<Screenshot
  src="/screenshots/chat-steer-queue.png"
  caption="While an answer is in progress, follow-up requirements queued above the input box" />

- **Add requirements midway**: you can keep typing while the agent is still working. Press Enter to queue a message for after the current step; press ⌘Enter / Alt+Enter to insert it into the current task immediately.
- **Fork and rewind**: fork a new conversation from any earlier question, or rewind in place to a given question; conversations that use a sandbox also restore the workspace to that point.
- **Thinking effort**: each conversation can choose the model's thinking effort separately.
- **Truncation notice**: answers truncated by the output limit are clearly marked instead of being cut off silently.

<Screenshot
  src="/screenshots/artifacts-library.png"
  caption="The sidebar Artifacts page: files generated by agents, collected across conversations" />

Files generated by agents are collected on the sidebar "Artifacts" page, where you can filter by type, search, view previous versions, and delete files you no longer need. When saving an answer to a knowledge base, the editor now shows a split view of Markdown source and preview, and supports saving drafts.

## Sandbox: graphical desktop, interactive terminal and local sandbox {#sandbox}

The "Sandbox" panel on the right of the conversation gains "Desktop" and "Terminal" tabs that give direct access to the same sandbox the agent is using.

<Screenshot
  src="/screenshots/sandbox-desktop.png"
  caption="Graphical desktop: operate the desktop environment inside the sandbox from the browser" />

<Screenshot
  src="/screenshots/sandbox-panel-terminal.png"
  caption="Interactive terminal: view workspace files and command results" />

- **Graphical desktop**: requires a Cube or E2B desktop template, with the desktop enabled in the sandbox configuration.
- **Interactive terminal**: available for Cube and E2B sandboxes; after refreshing the page you can reattach to a terminal that is still running.
- Opening the panel does not create or wake a sandbox; it disconnects automatically after a period of inactivity, 900 seconds by default.
- When the agent runs commands or installs skills, the tool card shows the output in real time.

**Lite desktop local sandbox (macOS)**: conversations without a remote sandbox selected run commands in the system sandbox. A new conversation can bind a project folder on the computer, and the agent can only write to that folder; commands cannot access the network, the `.git` directory is read-only, and credential directories are never accessible.

**Toolbox**: skills, MCP services and browser connection have moved from "Settings" to the sidebar "Toolbox", and the old settings entries redirect automatically.

## Model integration {#models}

Model integration is now organized in three layers, "protocol, provider, model catalog", with 27 built-in providers. When adding a model:

- After you choose a model from the provider catalog, the context window, max output, thinking effort and vision capability are filled in automatically.
- The "How this model is called" panel shows the request protocol, request URL and available thinking effort levels this model will use.
- When a particular API deviates from the defaults, you can override the protocol in the advanced options or provide a protocol-compat JSON.
- Speech recognition covers every provider whose documentation offers the capability.

## Knowledge bases and data sources {#knowledge}

- **Confluence data source**: supports Cloud and Server / Data Center, syncs published pages per space with incremental updates and deletion protection.
- **DingTalk document data source**; Tencent IMA sync now traverses subfolders.
- **Upload and parsing**: the upload panel shows overall progress and supports cancel and retry; the parsing timeline shows the duration of each stage and failure reasons; documents with no progress for a long time are marked "Queued" or "May be stuck".
- **Lists and downloads**: document and resource lists support sorting; original files can be downloaded in bulk as an archive.
- **Other**: document summaries can be turned off at upload time; knowledge base descriptions can be generated automatically from document profiles; FAQs can be filtered by enabled status; activity records show the name of the API Key used for an operation.

## Integrations, UI and security {#platform}

- **Web search**: adds Bocha and Serply; Brave and Serply support filtering by region and recency.
- **IM**: each channel can set its own reply language.
- **Japanese UI**: the UI adds Japanese, which can be switched in the UI or set as the default with `DEFAULT_LOCALE`.
- **CLI setup page**: "Settings → Publish & Integrations → CLI" walks you through installation and login in three steps.
- **Admin-created users**: system admins can create accounts directly in the console, generate a one-time password and copy the account details.
- **Whitelist-only egress**: with `SSRF_DNS_WHITELIST_ONLY=true`, domains not in `SSRF_WHITELIST` are rejected before DNS resolution, which suits offline or tightly controlled private deployments.

## Upgrade notes {#upgrade-notes}

| Change | What to do |
| --- | --- |
| `.env.example` no longer provides default values for `JWT_SECRET` and `SYSTEM_AES_KEY`, and adds `SYSTEM_SIGNING_KEY` | New deployments must generate their own. **Existing deployments must keep their original `SYSTEM_AES_KEY`**, otherwise saved credentials cannot be decrypted. When `JWT_SECRET` is not set, each process generates a random one, so logins become invalid after a restart and cannot be shared across replicas |
| The DingTalk IM channel only supports Stream mode | Migration `000096` automatically switches webhook channels to Stream; enable Stream mode for the app in the DingTalk developer console |
| Commands in the sandbox run as `root` by default (uid 1000 in v0.8.0) | Each conversation has its own sandbox, and the isolation boundary is still the container; scripts that depend on a regular user identity need to be adjusted |
| When updating an MCP service, `usage_instructions`, if provided, must be non-empty text of at most 16000 characters | Omit the field to keep the existing instructions |
| Organization invitations can only look up workspaces by exact workspace ID | Searching workspaces by name is no longer supported |
| The Go SDK's `UpdateAgentRequest.Avatar` is now `*string` | `nil` keeps the avatar, and an empty string clears it |

Database migrations: `000091`–`000110` for PostgreSQL and `000013`–`000030` for SQLite. Of these, `000106` creates indexes `CONCURRENTLY`; if it is interrupted, drop the invalid indexes first and then rerun the migration; see [FAQ and Upgrade Troubleshooting](../01-getting-started/05-troubleshooting.md). The ParadeDB image has been upgraded and can run on CPUs without AVX2; the MinIO image is now pulled from `quay.io`.

## Other improvements and fixes {#other-changes}

- **Agents**: retrieval tools are consolidated into `search_knowledge`, `read_document` and `list_documents`, with old tool names mapped automatically so no configuration migration is needed; conversation history is trimmed to the model's context window, and compaction checkpoints persist across turns; MCP tools are now discovered and called on demand, each service's tool directory is persisted, and individual tools can be enabled or disabled.
- **Skills**: upgrading older skill versions no longer rolls back the catalog or takes the skill offline midway; runtime dependencies are verified after installation.
- **Wiki**: full-page rewrites that get truncated are continued; entries with the same name reuse the page across types; cited chunks include image descriptions.
- **Retrieval and parsing**: Milvus supports multilingual BM25; Neo4j queries have limit protection; the PaddleOCR-VL request timeout is configurable; PDFs still use the built-in parser by default when anydoc is linked; inline HTML tables no longer produce oversized chunks.
- **Stability**: fixed several cases of documents getting stuck in "Processing" or "Deleting"; closed paths for cross-workspace access in shared spaces; Wiki tasks for deleted tenants no longer call models; request formats for embedding, rerank and some chat providers have been aligned with their official documentation.

For the full list, see the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).
