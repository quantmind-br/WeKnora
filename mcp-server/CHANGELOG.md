# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Added the `create_knowledge_from_text` tool: creates knowledge entries from manual Markdown text by calling the existing `/knowledge-bases/{id}/knowledge/manual` endpoint, completing the "text" portion of #323. Defaults to `status="publish"`, so entries enter the parsing/indexing pipeline and become searchable immediately after creation; pass `status="draft"` to save without indexing.
- Added the `update_knowledge_from_text` tool: updates manual Markdown knowledge via the existing `PUT /knowledge/manual/{id}` endpoint; re-indexes by default and can also save as a draft, completing #2378.
- Added the existing `create_knowledge_from_file` to the README tool list.

## [1.1.1] - 2026-07-30

### Changed
- The official PyPI package name changed to **`tencent-weknora-mcp`** (published via Trusted Publishing by the Tencent/WeKnora repository CI).
  The original community package `weknora-mcp` is not officially maintained — please migrate your install command.
- The project URL now points to the official [Tencent/WeKnora](https://github.com/Tencent/WeKnora) repository (`mcp-server/` directory).

### Fixed
- Restored `stateless_http=True` for the HTTP transport, matching the pre-migration `StreamableHTTPSessionManager(stateless=True)` behavior.
- Restored the SSE transport's message endpoint `/sse/messages/`, matching the pre-migration routing.
- `WeKnoraClient` now uses a thread-local `requests.Session`, avoiding session race conditions when MCP 2.x makes concurrent calls from a thread pool.
- File uploads (`create_knowledge_from_file`) now respect the `WEKNORA_VERIFY_SSL` setting.

### Notes
- When a tool call fails, MCPServer 2.x now returns `CallToolResult(isError=True)` (`ToolError`),
  rather than the old low-level API's behavior of returning a `"Error executing …"`-prefixed text block inside a successful response.
  Clients that only parse `content[0].text` will generally notice no difference; integrations that rely on the `isError` flag will now behave more in line with the MCP spec.

## [1.1.0] - 2026-07-30

### Fixed
- Fixed a server startup crash under MCP Python SDK 2.x (`AttributeError: 'Server' object has no attribute 'list_tools'`).
  SDK 2.0 removed the low-level `Server`'s decorator API (`@app.list_tools()` / `@app.call_tool()` / `app.get_capabilities()`),
  and since `uvx` resolves the published package to the latest 2.x, this caused the connection to be closed.

### Changed
- Migrated the MCP server implementation from the low-level `Server` API to the high-level `MCPServer` API (mcp 2.x, formerly known as FastMCP).
  - Rewrote all 28 tools as `@mcp.tool()` function signatures: input parameters use type annotations (schemas are auto-generated by the framework),
    descriptions come from docstrings, and return values are plain Python values serialized by the framework.
  - Switched the transport layer to `run_stdio_async()` / `sse_app()` / `streamable_http_app()`, with authentication still wrapped by `MCPAuthMiddleware`.
  - `WeKnoraClient`'s business logic (REST/SSE calls, resolve_*, wiki) remains unchanged.
- Bumped the dependency ceiling to `mcp>=2,<3` (aligning the published package with the dev environment, to prevent it from being resolved to a future breaking version again due to no upper bound).

### Notes
- This version requires a runtime environment with `mcp>=2`. If you temporarily need the older SDK, add `--with "mcp<2"` to your launch command, but upgrading to this version is recommended.

## [1.0.1] - 2026-07-28

### Fixed
- Redirected the entry-point scripts' (`run_server.py`, `main.py`, `run.py`) diagnostic output to stderr, preventing corruption of the MCP stdio protocol stream that was causing client startup failures
- Fixed a `ModuleNotFoundError` caused by `upload_paths.py` being missing from the wheel package
- Switched `__init__.py` to absolute imports, fixing package import errors during unittest/pytest test collection

### Changed
- Unified the PyPI distribution package name to `weknora-mcp` (command-line entry points `weknora-mcp-server` / `weknora-server` unchanged)
- Added a CI workflow (`.github/workflows/mcp-server.yml`), publishing under the tag format `mcp-server-v*`

### Startup Methods
1. `python main.py` - Main entry point (recommended)
2. `python run_server.py` - Original launch script
3. `python run.py` - Convenience launch script
4. `python weknora_mcp_server.py` - Run directly
5. `python -m weknora_mcp_server` - Run as a module
6. `weknora-mcp-server` - Command-line tool (after installation)
7. `weknora-server` - Command-line tool alias (after installation)
